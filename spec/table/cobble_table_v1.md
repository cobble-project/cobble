# Cobble Table V1 metadata and codec contract

`cobble-table-v1` is the cross-language physical codec used by Cobble tables. Rust and Java
implement the codec independently and must match the shared fixtures byte for byte.

## Metadata

Table metadata is UTF-8 JSON with:

- `format`: `cobble-table`
- `version`: `1`
- `schema`: the user-visible semantic schema
- `layout`: the physical mapping compiled by the Rust table layer

Field IDs are stable schema-evolution identities. A table primary key is an ordered list of
non-null scalar fields. The bucket key is a non-empty prefix of the primary key. Value fields are
mapped in schema order to contiguous Cobble columns starting at zero.

The layout fingerprint is generated by the Rust layout compiler as lowercase SHA-256 over its
canonical compact JSON serialization of:

1. layout version;
2. codec identifier;
3. the complete table schema;
4. key fields;
5. bucket fields;
6. value-column mappings.

Language bindings consume the persisted fingerprint; they do not recompute it using their own
JSON serializer.

## Logical types

V1 defines Boolean, signed integers, floating-point numbers, Decimal, Date, Time, Timestamp,
String, Binary, List, Map, Struct, and Extension. Nullability belongs to every logical type node.
Map keys cannot be nullable.

Primary-key fields are limited to Boolean, signed integers, Decimal, Date, Time, Timestamp,
String, and Binary. Floating-point and nested values are not V1 key types.

## Binary codec

The exact key, value, row, and JNI batch encodings will be specified with shared golden vectors in
Phase 2. Persisted values must always declare `codec = "cobble-table-v1"`; readers reject unknown
codec identifiers rather than guessing.

## Evolution

Metadata, layout, and binary codec versions evolve independently. A future version adds a new
identifier and does not silently reinterpret V1 bytes.
