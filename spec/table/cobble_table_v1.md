# Cobble Table V1 metadata and codec contract

`cobble-table-v1` is the cross-language physical codec used by Cobble tables. Rust and Java
implement the codec independently and must match the shared fixtures byte for byte.

## Metadata

Table metadata is UTF-8 JSON with:

- `format`: `cobble-table`
- `version`: `1`
- `schema`: the user-visible semantic schema
- `layout`: the physical mapping compiled by the Rust table layer

Field IDs are stable schema-evolution identities. A table primary key is an ordered list of
non-null scalar fields. The bucket key is a non-empty prefix of the primary key. Value fields are
mapped in schema order to contiguous Cobble columns starting at zero.

A table with no semantic value fields still creates one internal presence column. It records that
the key exists; it is not part of the semantic layout or returned row values.

The layout fingerprint is generated by the Rust layout compiler as lowercase SHA-256 over its
canonical compact JSON serialization of:

1. layout version;
2. codec identifier;
3. the complete table schema;
4. key fields;
5. bucket fields;
6. value-column mappings.

Language bindings consume the persisted fingerprint; they do not recompute it using their own
JSON serializer.

## Logical types

V1 defines Boolean, signed integers, floating-point numbers, Decimal, Date, Time, Timestamp,
String, Binary, List, Map, Struct, and Extension. Nullability belongs to every logical type node.
Map keys cannot be nullable.

Primary-key fields are limited to Boolean, signed integers, Decimal, Date, Time, Timestamp,
String, and Binary. Floating-point and nested values are not V1 key types.

## Binary codec

Encoding is schema-directed: bytes contain no type tag. All key fields must be non-null and are
concatenated in primary-key order. Signed fixed-width integers, Decimal, Date, Time, and the
seconds portion of Timestamp use big-endian two's-complement with their first byte XORed by
`0x80`, so unsigned byte comparison preserves signed order. Timestamp nanos are unsigned
big-endian. String and Binary keys escape every `00` as `00 ff` and terminate with `00 00`.

Values use a `00` / `01` marker only for nullable nodes. Int8/16/32/64, Decimal, Date, Time, and
Timestamp use the same ordered big-endian fixed-width payloads as keys; Timestamp nanos are
unsigned big-endian. Boolean remains one `00` / `01` byte, while Float32/64 remain little-endian
IEEE payloads and do not define bytewise ordering. String and Binary payloads are their raw bytes.
Decimal width is four bytes for precision 1--9, eight for 10--18, and sixteen for 19--38. Time and
Timestamp precision is 0--9; Time is an i64 nanos-of-day and Timestamp is i64 seconds followed by
u32 nanos. List and Map start with a u32 little-endian count; every child uses `u32 little-endian
length + payload`. Struct has its schema fields in order, each with the same length-delimited child
format. Extension encodes exactly its declared physical type. Container encodings do not define
bytewise comparison semantics.

Rust `ValueCodec::decode_bytes(Bytes)` returns Binary values that retain the input allocation via
`Bytes` reference counting, so callers need not keep another input handle alive. Java
`ValueCodec.decode(ByteBuffer)` returns Binary values as borrowed read-only slices, including
nested values; if their backing buffer will be reused or mutated, applications must copy them.

`BucketHash` applies Java `Arrays.hashCode(byte[])` semantics (signed bytes, wrapping i32) to the
encoded bucket-key prefix and then uses `floorMod`. Bucket counts are in `[1, 65536]`.

The comprehensive cross-language vectors are in
[`fixtures/cobble_table_v1_codec.json`](fixtures/cobble_table_v1_codec.json). Persisted values
must always declare `codec = "cobble-table-v1"`; readers reject unknown codec identifiers rather
than guessing.

## Evolution

Metadata, layout, and binary codec versions evolve independently. A future version adds a new
identifier and does not silently reinterpret V1 bytes.
